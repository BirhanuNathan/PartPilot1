# AGENTS.md — guide for AI coding agents working on PartPilot

PartPilot is a Vite + React SPA with Netlify Functions. Two Claude tool-use agents find and verify CAD parts from a parts catalog, and two automations (an approval pipeline and a weekly gap report) persist everything to Netlify Blobs. Product docs are in `README.md`, `docs/AGENTS.md` (the AI agents), and `docs/AUTOMATIONS.md`.

## Layout

```
data/parts.json                 seed catalog, generated by scripts/generate-catalog.mjs (edit the script, not the JSON)
netlify.toml                    build, functions dir, /api/* → /.netlify/functions/:splat, SPA fallback
netlify/functions/*.mts         one file per endpoint; the URL is /api/<filename>
  find-parts.mts                Part Finder agent (NDJSON stream)
  verify-fit.mts                Fit Checker agent (NDJSON stream) + deterministic guardrails
  approve.mts                   Automation 1
  weekly-report.mts             Automation 2, scheduled @weekly (no URL in prod)
  run-weekly-report.mts         Automation 2 manual trigger
  admin.mts, bom.mts, import-package.mts, request-review.mts, log-search.mts
netlify/functions/lib/*.ts      shared server code (.ts, so Netlify never treats these as functions)
  catalog.ts                    ONLY data-access layer for parts (searchCatalog/getPart/listCategories, LIBRARY_BASE_URL)
  compat.ts                     deterministic rule engine (pure; also imported by the browser for demo mode)
  agent.ts                      generic Messages API tool loop (5 iterations, 1500 max_tokens, zod validation + 1 retry)
  tools.ts                      tool definitions (zod → JSON Schema via z.toJSONSchema)
  prompts.ts                    system prompts, CAD rulebook, MODEL constant
  schemas.ts                    zod schemas + shared types (the front end imports types from here)
  store.ts, notify.ts, automation.ts, bom.ts, weekly-report.ts, http.ts
src/                            React app
  pages/                        FindParts (home), Bom, Admin, About, NotFound
  components/                   NeedResult (result card), StepTrace, Layout, ui.tsx primitives
  demo/examples.ts              the 3 example prompts (small, always bundled)
  demo/traces.ts                recorded demo runs (lazy-loaded via dynamic import)
  lib/                          api.ts (fetch + NDJSON reader), image.ts (validate/resize), demoMode.tsx, types.ts
public/examples/*.svg           sample CAD screenshots (rasterized to JPEG in the browser before sending)
```

## Conventions

- Functions use the modern default export `(req: Request, context: Context) => Response`, which AI Gateway credentials require. Read env with `Netlify.env.get`.
- Do not set `config.path` on functions. Routing comes from the `/api/*` redirect in `netlify.toml`, so the filename is the route.
- Never pass an API key to `new Anthropic()`. AI Gateway injects it. Use model `claude-sonnet-5-5` from `prompts.ts`.
- Validate every request body and every LLM JSON output with zod. Resolve part ids against `getPart` on the server, and never trust part data sent by the client.
- Blobs: one store, `partpilot`, with strong consistency. Key prefixes are `searchlog/`, `runs/`, `notifications/`, `audit/`, `packages/`, `reports/`, `ratelimit/`, plus `bom/default` and `reports-latest`. Timestamped keys come from `timeKey()` so they sort chronologically.
- Agent endpoints stream NDJSON `AgentStreamEvent`s (`step` / `result` / `error`). The client reader is `streamAgent()` in `src/lib/api.ts`.
- Styling: Tailwind v4 with custom utilities in `src/index.css` (`btn-primary`, `btn-secondary`, `btn-ghost`, `card`, `chip`, `label-caps`, `grid-paper`). Neutral zinc grays and one accent (`accent-*`, blueprint blue). Verdict colors are semantic (emerald/amber/red). Part numbers and dimensions use `font-mono`.
- Every async UI state needs a loading, empty, and error state. The app must never show a blank screen (there is an `ErrorBoundary` at the root).

## Non-obvious decisions

- **Streaming instead of a background function:** each agent finishes in about 25 s, which fits inside a synchronous streamed function, so the UI gets live steps without polling.
- **Sonnet 5.5 request tuning:** `agent.ts` sends `thinking: { type: 'between_tools' }` and `output_config.effort: 'medium'` to keep turns fast and within 1500 tokens. On a 400 it retries without them. Forced `tool_choice` (`any`/`tool`) is not supported on this model, so the final turn uses `tool_choice: none` plus an instruction.
- **Guardrails beat the LLM:** `verify-fit.mts` re-runs `checkCompatibility` on each final pick and can only make a verdict stricter, never looser.
- **Demo mode** must keep working offline. If you change catalog part numbers, update `src/demo/traces.ts`, which throws on unknown part numbers.
- Catalog ids (`P0001`…) are assigned in generation order. Regenerating with a different order changes ids, so demo traces reference part numbers instead.
